## 2. Co nie działa

| Źródło | Objaw | Przyczyna |
|---|---|---|
| **yfinance** | `SSLError: curl (35) Recv failure` na każdym tickerze | silnik `curl_cffi` podszywa się pod TLS-fingerprint Chrome; proxy re-terminuje TLS, więc impersonacja nie przechodzi. Bez `impersonate` połączenie wstaje, ale Yahoo odpowiada 429 |
| **Yahoo bezpośrednio (httpx)** | pierwsze zapytanie 200, kolejne **429 Too Many Requests** | limit per IP, a IP proxy jest współdzielone. Dotyczy też `/v1/test/getcrumb`, więc flow z crumb również odpada |
| **stooq** | HTML z challenge JS zamiast CSV | anty-bot proof-of-work. Obejście = scraping zabezpieczenia, czego SPEC zabrania |
| **Finnhub `/stock/candle`** | HTTP 403 | historia OHLC jest poza darmowym planem |
| **Finnhub `/stock/option-chain`** | HTTP 403 | łańcuch opcji jest poza darmowym planem |
| **Finnhub `/stock/split`** | HTTP 403 | poza darmowym planem — istotne dla polityki korekt o splity |

## 3. Wniosek: blocker dla kroków 4–8

**Nie mamy w tym środowisku ani łańcucha opcji, ani historii cen OHLC.**

Konsekwencje wprost:
- bez łańcucha opcji **nie ma czego liczyć** w `engine/expected_move.py` (krok 4) i w `scan` (krok 5)
- bez historii OHLC **nie da się rozliczyć** zdarzeń w `settle` (krok 6) ani zbudować zbioru
  treningowego w `backfill` (krok 8) — a to zbiór treningowy fazy 2

Kroki 1–3 (szkielet, CI, warstwa źródeł kalendarza, modele, baza) są wykonalne od zaraz.

**To ograniczenie środowiska, nie kodu.** Na lokalnej maszynie yfinance najprawdopodobniej działa
normalnie — nie ma tam ani MITM proxy łamiącego impersonację TLS, ani współdzielonego IP
wpadającego w limity Yahoo.
